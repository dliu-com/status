How it works

Every 15 minutes, status.dliu.com visits each dliu.com site the way a guest would (no sign-in, no cookies) and decides whether each of its functions is up, degraded or down.

Up, degraded or down

Upevery check passed
Degradedslow (over 3 s), reported "warn", or failed once
Downfailed two runs in a row
  • A site is down when one of its essential functions is down, and degraded when any function isn't fully working (an optional one, such as Docs, being down only makes it degraded).
  • A failed check is tried again 2 seconds later in the same run, so one lost request doesn't count.
  • Availability counts degraded as available; only down time lowers it.
  • Private sites are checked too but not shown here.
Technical details
  • Checker: Lambda Checker (Node.js 22, arm64), EventBridge rate(15 minutes), 90 s timeout. Each request: 10 s timeout, redirect: manual, no cookies, user agent dliu-status-bot/1.0 (+https://status.dliu.com/docs).
  • Definition: config/apps.json in dliu-com/status. Each site has functions, and each function has checks (URL, method, expected status, content type, body marker, JSON key or redirect target). Sites with a backend also answer GET /health in application/health+json; the contract is HEALTH.md.
  • State (failure streaks, 90 days of daily counts, the last 24 h, incidents) is kept in a private S3 bucket; the public summary is /data/status.json, cached for 60 s.
  • traffic.dliu.com drops requests with this user agent, so checks never count as visits.

Why no CloudWatch metrics

Reading Lambda and CloudFront metrics for every site every 15 minutes would cost about $2 a month with GetMetricData, over the limit. The checks are instead purely what a guest sees, plus each site's own /health.
